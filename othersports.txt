Recommended Architecture: Sport Configuration System
Instead of 16 separate folder structures, you'd want a data-driven approach:

1. Single Shared Codebase with Sport Configs
/frontend
  /player          # ONE player folder (shared templates)
  /coach           # ONE coach folder (shared templates)
  /sports-config   # Sport-specific configurations
    /football.json
    /basketball.json
    /soccer.json
    ...
Each sport config JSON would contain:
Positions for that sport
Stats relevant to each position
Top 3 stats for transfer portal display
Any sport-specific terminology

2. How It Would Work
The UI templates stay the same, but they dynamically render based on:
User's selected sport (stored in their profile)
Sport configuration file loaded at runtime
For example, your stats form would read from config:
const sportConfig = await loadSportConfig(user.sport);
const positions = sportConfig.positions;
const statsFields = sportConfig.stats[selectedPosition];
// Render form dynamically

3. Database Changes
Add a sport field to relevant tables (PlayerProfile, CoachProfile, etc.) and make stats 
storage flexible (JSONB fields work great for variable stat structures).
