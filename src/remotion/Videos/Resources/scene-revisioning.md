## Purpose
When the user gives feedback, suggestions, additions, or changes to a scene, do not overwrite or replace the original scene.
Instead, create a new version of that scene.
This keeps the workflow clean, preserves previous iterations, and makes the revision history easy to track.
________________________________________
Core Rule
If the user suggests any change to an existing scene:
•	Do not edit the original scene in place 
•	Do not delete the previous version 
•	Create a new scene version directly after it 
Each new revision must be labeled as:
•	Scene X V2 - [Original Scene Name] 
•	Scene X V3 - [Original Scene Name] 
•	Scene X V4 - [Original Scene Name] 
And so on.
________________________________________
Naming Format
Use this exact structure:
Scene [number] V[version] - [scene title]
Examples
Original:
•	Scene 2 - The Workflow Problem 
First revision:
•	Scene 2 V2 - The Workflow Problem 
Second revision:
•	Scene 2 V3 - The Workflow Problem 
Third revision:
•	Scene 2 V4 - The Workflow Problem 
________________________________________
How To Behave When The User Makes Suggestions
If the user says things like:
•	“Add this to Scene 2” 
•	“Change Scene 4” 
•	“Make Scene 1 feel faster” 
•	“Update Scene 3 with this idea” 
•	“Revise Scene 5” 
•	“Try another version of Scene 6” 
You should treat that as a revision request, not a replacement request.
That means:
1.	Keep the existing scene untouched 
2.	Create a new version of that same scene 
3.	Carry over the original scene title 
4.	Apply the requested changes in the new version only 
________________________________________
Revision Workflow Rule
Always use the latest version of the scene as the base for the next revision.
Example:
•	Scene 2 - The Workflow Problem 
•	user gives feedback 
•	create Scene 2 V2 - The Workflow Problem 
Then if the user gives more feedback on Scene 2 again:
•	do not go back to the original 
•	build from Scene 2 V2 
•	create Scene 2 V3 - The Workflow Problem 
This continues for every revision.
________________________________________
Important Rule
The scene number stays the same.
Only the version number increases.
So if the user is still revising Scene 2, it always remains Scene 2 — just with updated version labels like V2, V3, V4.
Do not rename it to a different scene number.
________________________________________
Goal
This versioning system exists to:
•	preserve previous ideas 
•	avoid confusion 
•	track revisions cleanly 
•	make side-by-side comparisons easier 
•	keep the workflow organized and professional 
________________________________________
Example Behavior
User says:
“Add this to scene 2.”
Correct output:
•	Scene 2 V2 - [same original scene title] 
User says:
“Now revise that again.”
Correct output:
•	Scene 2 V3 - [same original scene title] 
User says:
“Make another updated version.”
Correct output:
•	Scene 2 V4 - [same original scene title] 
________________________________________
Final Rule
Never replace. Always version.
If the user suggests a change to an existing scene, create a new scene version using this format:
Scene X V2 - Original Scene Title
Then continue with:
Scene X V3 - Original Scene Title
Scene X V4 - Original Scene Title
Every new suggestion creates a new version.
